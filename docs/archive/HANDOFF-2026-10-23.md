## Current architecture and files

The direction implemented is local JSON authoring plus an offline compiler plus a static React site. No database, hosted editor, login, paid API, or new service was added.

### Pipeline and tools

- `scripts/lib/catalog.mjs`: loading, validation, reference checks, compilation, hashes, atomic JSON writes that skip unchanged output.
- `scripts/migrate.mjs`: one-time non-destructive migration. Refuses to overwrite `data/events`. **Do not rerun or bypass that guard.**
- `scripts/build-data.mjs`: offline validation, media integrity checks, generated summary index, full per-event detail JSON, and standalone public reference exports.
- `scripts/catalog.mjs`: CLI find/show/list/add. Allocates a new ID from the maximum existing numeric ID; no renumbering.
- `scripts/local-editor.mjs`: Vite development middleware, loopback only, strict Origin check on writes, JSON/body limits, optimistic file hash, validation, backup before save, source write, and offline rebuild. No hosted write API.
- `scripts/check-local-editor.mjs`: integration smoke script against a running local server. Tests reads, origin rejection, stale edit rejection, invalid year rejection, backup, exact no-op save, and rebuild. **Written but not yet run.**
- `scripts/lib/wikimedia.mjs`: explicit source/file parsing, MediaWiki API helpers, host allowlist, bounded response reads, timeouts, plain-text credit extraction, recognized-license allowlist.
- `scripts/sync-sources.mjs`: opt-in sequential Wikipedia intro/image retrieval with delays, local snapshots, backup, image hash paths, 80 MB per-run new-image budget, and stop after three consecutive record failures. It preserves existing data on failure. It has no automatic retry/backoff yet.
- `scripts/export-content.mjs`: offline Markdown or printable HTML reading copy under `.local/exports/`. HTML has Print / Save as PDF.

## Data findings that must remain visible

Original JSON has 574 rows, 456 with numeric starts, 118 with null starts, 13 without a name, 419 image URLs, 417 nonempty extracted article texts, and 169 distinct literal location labels. All legacy country fields were empty.

One dated legacy row, Christianity / numeric ID 179, used year zero. The new canonical record has `start: null`, status stub, and an explanation; `legacy.originalStart: 0` and the untouched original JSON preserve the original. Therefore the new catalog currently has **455 dated / 119 undated** records. Do not invent a replacement year.

Legacy geocodes are severely unreliable: “Universe” points to a business in Denmark, “Milky Way” points to a place in Seychelles, and blank locations frequently resolve to the same Italian village. All original geocoder output is preserved under `legacy`, but none is promoted into reviewed map coordinates. At present no places have been reviewed, so the new event pages will not display maps until references are curated.

31 legacy `range_type=1` rows are conservatively represented as uncertain bounds, with an explicit note to review their meaning. Do not convert these to durations without examining the source. Some names have encoding damage; do not silently guess repairs.

Time scales have unset color placeholders, nesting issues, overlaps, regional human-period assumptions, legacy spelling, and stale present/future cutoffs. They are reusable and preserved, but **not newly source-verified**. Last audit found 85 unset colors and 15 child ranges outside their parent. They need a deliberate sourced review.
